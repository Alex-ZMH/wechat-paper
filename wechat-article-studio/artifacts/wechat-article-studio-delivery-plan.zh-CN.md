### 3.2 最小启动实现

- 新中文入口复用 scripts/start-workbench.ps1。
- 原 START-WORKBENCH.cmd 作为兼容入口保留；两个入口调用同一个启动实现。
- 服务已经运行且属于本项目时直接打开，不再起第二实例。
- 未运行时自动启动、等待 /api/health 就绪，然后打开默认浏览器。
- 用户不用手工执行 npm start、寻找端口或输入 URL。
- 中文正常入口不应意外继承 WECHAT_STUDIO_NO_BROWSER=1 而只启动不打开；该开关保留给底层脚本的隔离测试，处理仅限启动子进程环境，不改用户全局环境。
- 普通启动只显示简短结果；失败时显示原因，不能隐藏失败窗口后悄悄退出。
- 只监听本机回环地址，不为省事绑定 0.0.0.0 或开放局域网。
- 保留原有内部默认端口和 origin，避免给未保存副本制造迁移问题。
- 不新增自动随机端口、浏览器专用用户目录或所谓桌面壳。
- 端口被其他程序占用时准确报告，不杀未知进程、不打开其他程序页面。此类真实冲突不是新增审核门禁。

“不绑定 IP”在本计划中的含义是用户不再操作地址，脚本负责入口；不是把有后端的工作台改为 file:// 双击静态 HTML。完全取消本机 HTTP 需要更换运行容器，不属于本次要求的最小实现。

## 5. 哈希、来源与数据兼容政策

### 5.1 哈希处理

| 用途 | 处理 |
|---|---|
| 内容指纹决定审查通过资格 | 删除活动审批依赖 |
| humanApproval.fingerprint/draftHash 控制定稿或文件名 | 删除资格判断 |
| 缺少 content-reviews 回执阻止使用 | 删除 |
| 旧 ID、历史字段和版本去重摘要 | 兼容读取，不做全项目替换 |
| 启动器数据目录 scope / 活跃任务去重 | 属于实例与请求识别，保留，不是文章审核 |
| 当前工作区 version/baseVersion | 保留防覆盖用途，不重建版本审批 |

禁止只隐藏按钮、后端自动补审核 hash、全部 gate 返回 true 或批量写 approved。

### 5.2 来源与检查语义

- 自动搜集完成只表示真实调用返回可用资料，不表示独立核验全部完成。
- sourceOrigin 继续准确记录自动搜集或用户导入，只用于内部审计。
- 原文摘录与模型整理要点必须在自然语言层面区分，无法确认原文时不加引号伪装直接引语。
- 单条资料缺失字段时，保留原始记录、指出未采用项、保留其他可用资料；不得静默缩小结论范围。
- 未完成可选检查不妨碍使用。实际为空、无效 JSON、错误引用仍需真实报错。
- 可选检查遇到 403、验证码、模型格式错误时报告自身失败，不回写成整个研究从未获得结果。

### 5.3 最小旧数据兼容

1. 先备份、后对副本验证；代码回退与用户新数据分开处理。
2. 保留工作区、资料、文章、批注、revision、来源映射和运行记录。
3. 旧审核字段可读但不决定新操作资格；不要求重写全库，也不为了清理删记录。
4. 同一旧存档多次打开，不产生重复文章、不改变原有 ID。
5. 已损坏数据明确报告，不能通过取消审核把损坏解释为可用。
6. 浏览器未保存副本继续留在原 origin。无必要不换端口、主机名或用户配置目录。
