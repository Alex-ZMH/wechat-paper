# 公众号文章工作台：启动与使用

当前版本支持实时研究和独立导入资料。自动搜集通过已登录的本机 Codex CLI 联网取得结构化资料，来源与论点关系有效即可进入大纲；逐页来源检查和内容检查是可选建议，不是写作许可。资料不足或调用失败会如实提示，不换用样例。

## 启动

直接双击项目根目录的 `打开公众号工作台.cmd`。它会复用已运行的工作台；未运行时固定以 `43210` 端口和本项目 `data` 目录启动、等待健康检查通过，并打开默认浏览器，不受隔离测试环境的 `WECHAT_STUDIO_PORT` / `WECHAT_STUDIO_DATA_DIR` 影响。即使当前环境误带 `WECHAT_STUDIO_NO_BROWSER=1`，中文入口也会在自己的启动子进程中清除该测试开关并打开浏览器；不会修改用户的全局环境变量。启动失败时窗口会保留并显示准确原因。

原有的 `START-WORKBENCH.cmd` 继续保留为兼容入口；底层 PowerShell 脚本的 `WECHAT_STUDIO_NO_BROWSER=1` 仍可用于不打开浏览器的隔离测试。

开发者也可以在 PowerShell 中手动执行：

```powershell
Set-Location 'C:\Users\ironman\Desktop\wechat\wechat-article-studio'
npm start
```

正常使用无需输入地址、端口或命令。明确保存的文章保存在本项目内。

依赖：Node.js 20+、已登录的 Codex CLI、可用的 Python/python-docx。普通 PowerShell 的 writer 会查找 PATH 中的 `codex.exe`；若显式配置 `CODEX_BIN`，必须指向有效程序。导出和服务错误只进入开发记录，不进入文章。

## 现在可以使用的路径

1. 填写选题、读者、文章目的、长度和文风。另起选题使用“另写一篇”；已有文章的“修改选题与要求”会保留原文章并另起一篇。
2. 点击“开始查资料”。研究在服务后台运行，关闭浏览器不会中止；重新打开页面会继续显示任务。需要停止时点击“停止搜集”。
3. 也可以点击“导入已有资料”，选择研究资料文件；预览来源、摘录、日期和链接，选择匹配资料后确认。
4. 资料完成后，可直接使用已有大纲，也可编辑章节与论点、增删和排序。同一论点可以出现在不同章节；点击“生成初稿”会采用当前大纲，无需单独审批。生成失败保留资料与大纲，不补样例文章。
5. 在中央逐段编辑。点击段落，右侧查看来源；切到“批注”添加意见。原文不会因加批注被替换。处理后点击“标记已解决”。
6. 点击“保存修改”，看到“已保存”才表示已写入本地。保存失败会保留当前内容，可直接重试。
7. “检查文章（可选）”提供事实、数字、逻辑、重复表达和文风建议；检查失败或有未解决高优先级批注，也可正常保存与下载。
8. 点击“下载 Word”会先保存未保存的当前修改，再导出该保存版本。保存失败不下载旧稿。文件名为文章标题 `.docx`，正文不含后台状态。

## 数据与检查

- 正常工作数据：项目 `data`。历史审核字段和回执保留但不再决定文章使用资格；不要手工修改文章和历史记录。
- 如果服务器或恢复校验失败，浏览器会保留副本并标记为未保存；服务恢复后可重试保存，不会用空白状态覆盖副本。
- 本轮验收在独立目录中运行，不会把测试文章载入你的默认工作区。
- 早期含操作测试文字的 MOF 工作区已保留并备份，不会自动当成新选题结果。
- `npm test` 和 `npm run check` 只检查程序，不代表实时研究、来源独立核验、内容复核或用户人工验收成功。
- 开发证据见 `evaluation/CORE-REPAIR-20260904.md`。
- 本轮实际结果见 `evaluation/IMPROVEMENTS-20260922.md`。实时任务可能因原文、论点或引用范围不完整而失败，不能保证任意新主题都成功；已核验资料是独立路径，不是自动替代。
