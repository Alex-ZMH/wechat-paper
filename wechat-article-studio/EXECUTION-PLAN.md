## 1. 推荐执行智能体

### 1.1 首选配置

| 项目 | 建议 |
|---|---|
| 执行环境 | 本机 Codex，直接使用现有项目目录 |
| 主智能体角色 | 负责交付的全栈工程师 |

这是针对当前任务的工程建议，不是要求固定全局模型，也不是要求修改工作台内部 research/writer 的模型配置。

选择理由：

1. 本次不是单文件修复，而是移除前端、服务端、审查、导出之间的多处审批依赖，需要一个主负责人追踪完整调用关系。

3. 本机执行可以直接验证已有 Node 服务、已登录的 CLI、浏览器和本地 Word 导出路径。
4. Luna 适合有明确输入、文件范围和验收条件的执行任务，不建议把跨模块政策取舍全部交给多个子智能体分别决定。

OpenAI Docs 的官方最佳实践建议复杂修改和调试使用 Medium 或 High，并将有边界的探索、测试等工作交给子智能体。这里选择 High 和单一主负责人，是结合本项目风险作出的判断，而不是官方对本项目的指定配置。[官方最佳实践](https://learn.chatgpt.com/guides/best-practices?translationFallback=es-419)

## 3. 产品目标和正常流程

```text
输入选题
  → 实时搜集资料，或显式导入已有资料
  → 查看来源与大纲
  → 生成文章
  → 编辑、批注、保存
  → 下载当前版本 Word
```

“检查文章”是可选辅助，不是必经步骤。

具体目标：

1. 研究返回有内容的结构化资料后，用户可以看到并使用。
2. 不要求每个来源都被第二套程序重新抓取成功。
3. 不要求第二个模型逐条同意，研究结果才能保存。
4. 不用内容哈希、审核回执和人工审批控制下载。
5. 批注和检查意见仍然保存、显示，但不锁住文章。
6. 保留真实写作、编辑、来源查看、保存恢复和 Word 排版。
7. 不因“实验”“未签字”等分类继续推迟已可用功能。

明确的取舍：自动研究结果不再等同于全部经过独立核验的结果。来源、限制和检查意见仍可查看，但平台不再强制完成一套审计程序。界面和文档必须准确说明这一变化，不能把取消审计写成全部核验成功。

## 4. 现状与处理矩阵

| 当前机制 | 实际影响 | 修改方向 |
|---|---|---|
| 搜索后逐页重新抓取全部来源 | 单篇论文返回 403，整次研究失败 | 移出研究必经路径 |
| 摘录严格字符串匹配 | 标点、网页模板或验证码页面可能触发整体失败 | 改为可选检查结果 |
| 第二次 AI 审核全部论点 | 已有资料不能进入大纲 | 取消强制调用 |
| 内容指纹与审核回执 | 修改正文后必须重新审核 | 删除审批依赖 |
| 高优先级批注门禁 | 用户批注锁住交付 | 改为醒目提醒 |
| 强制人工定稿 | 文件名和下载受审批控制 | 删除必经步骤 |
| 每段至少绑定一个 claim | 过渡段也被迫附会证据 | 允许空 claimIds |
| 所有选中论点必须写入 | 强塞内容、重复表达 | 改为写作建议 |
| 同一论点不能跨章节使用 | 正常前后照应受限 | 删除限制 |
| 单段超过 600 字、全文超过 24 段阻断 | 排版建议变成门禁 | 改为提示 |
| 必须单独确认大纲 | 多一次强制操作 | 生成时采用当前大纲 |
| 未保存不能点击下载 | 下载前需手动额外操作 | 下载先保存，再导出该版本 |

这些修改是政策调整，不意味着先前的 403、验证码、模型错误或无效结果不存在。外部调用真正失败时仍必须如实报告。

## 5. 删除哈希审核的准确范围

### 5.1 删除审批用途

- 删除 `contentFingerprint()` 对文章使用资格的控制。
- 删除 `workspaceContentFingerprint()` 对定稿和导出的控制。
- 删除以内容指纹为键的强制审核回执依赖。
- 删除“没有当前哈希审核记录就不能交付”的分支。
- 删除“修改文章后必须重新审核才能下载”的分支。
- 删除 `humanApproval.fingerprint`、`humanApproval.draftHash` 对下载资格和普通文件名的控制。
- 删除缺少审核记录时自动插入阻断问题的逻辑。
- 审核记录文件异常不得影响文章恢复、编辑、保存和导出。

旧审核记录保留为历史数据；不再决定当前文章能否使用。

### 5.2 不进行全项目哈希字段迁移

`makeId()` 和部分 hash 字段还用于内部 ID、版本关联、历史去重，不能机械删除。本文删除的是哈希审批机制，不是要求清除所有计算哈希的代码。

- 保留旧存档中的 `draftHash`、`packetHash` 等兼容字段。
- 不全局替换内部 ID，不批量重写历史 parentIds。
- 保留现有工作区 `version`/`baseVersion`，防止旧页面覆盖新保存内容。
- 保留旧批注不能错误应用到另一稿件或不存在段落的保护。
- 不用新的“版本审批回执”替代旧的哈希审批，避免换名重建同一套门禁。

### 5.3 验收

- [ ] 没有审核回执，可以生成、保存和下载。
- [ ] 修改正文后，不重新审核也能下载新版本。
- [ ] 旧文件携带审核 hash 不影响恢复。
- [ ] 旧审核记录缺失不影响文章使用。
- [ ] 没有通过把所有状态强行改成 `approved` 假装完成。

## 6. 仅保留的基本运行保护

以下不是内容审批，不删除：

1. **可解析**：结构化结果能读取；空文章、无效 JSON 不能当作成功。
2. **不串稿**：选题、资料、大纲和正文属于同一工作区；旧响应不能覆盖新选题。
3. **不丢稿**：保留原子保存、版本冲突检查、失败时保留页面内容和历史版本。
4. **引用不乱配**：有引用时必须指向实际存在的资料；不能虚构引用编号。
5. **不谎报**：失败不套样例；导入不冒充联网；未独立核验不声称已核验。
6. **基本安全**：保留输入类型检查、路径范围、HTML 转义和读者/内部字段分离。

“允许实验功能正常使用”不授权把固定样稿当成真实 writer 输出，也不授权把测试数据自动载入用户工作区。
