# AI4S 调研项目交接文档

> 面向完全没有上下文的新会话。交接日期：2026-09-03（中国标准时间）。

## 1. 我们在做什么

这是一个面向微信公众号的 AI for Science（AI4S）行业调研与配图项目，原始需求是：

- 判断 AI4S 是真实可落地的技术，还是被融资叙事放大的“庞氏骗局”；
- 分析中国公司和科研院所，重点包括材科源图、深度原理、深势科技、晶泰科技、开物纪、苏州实验室等；
- 覆盖优势、劣势、融资、估值/市值、产品布局、实验与商业化证据；
- 输出一篇可用于公众号的长报告，配大尺寸、具有争议性和传播力的图片、表格和文案。

项目采用的核心判断不是简单二分“真/假”，而是把四种证据拆开：

1. 技术可复现：论文、代码、数据、强基线、OOD/失败案例；
2. 实验/临床兑现：合成、表征、器件、产率、寿命或临床终点；
3. 商业兑现：采购订单、验收、回款、复购、审计收入；
4. 透明度：客户身份、失败率、收入结构、现金消耗和估值口径。

最终结论是：**AI4S 本身不是庞氏骗局，但行业中存在“用下一轮融资证明上一轮技术价值”的庞氏式增长叙事。技术真实、实验成功、规模化交付、持续赚钱是四件不同的事。**

## 2. 已经完成了什么

### 2.1 调研与结论

- 深拆 6 个重点对象：晶泰科技、深势科技、深度原理、开物纪、材科源图、“苏州实验室”（特别区分苏州国家实验室与姑苏实验室）。
- 扩展到约 20 个国内公司/品牌，包括镁伽、龙讯旷腾、鸿之微、迈高材云、武汉智化、百图生科、分子之心、望石智慧、剂泰科技、予路乾行等。
- 调研北京科学智能研究院、DeepModeling、智源、中科院物理所/自动化所、中科大机器化学家、上海人工智能实验室、西湖大学等科研平台。
- 纳入全球对照：DeepMind/AlphaFold/GNoME/A-Lab、微软 MatterSim/MatterGen 与 PNNL 电池案例、Schrödinger、Recursion/Exscientia、Isomorphic Labs、Citrine。
- 建立 A/B/C/D 证据等级：
  - A：已有审计收入、持续续费、临床或第三方实物验证；
  - B：真技术、早期转化，论文/开源/硬件扎实，但规模化或复购未证；
  - C：团队和融资真实，但关键性能、客户、订单主要是公司自报；
  - D：只有在虚构论文/客户/融资，或法院、监管、合作方认定时使用。
- 本次公开资料审阅**没有足以把被点名公司定为 D 的证据**，所以正文使用“证据不足”“宣传跑在验证前”“高风险”等表述，不把事实未证等同于诈骗。

## 3. 当前卡点

当前没有技术性阻塞，项目已经具备发布初稿的条件。但以下事项在正式发布前必须处理：

1. **时效性**：研究截止是 2026-08-18，现在是 2026-09-03；晶泰市值、私营公司最新融资、临床进展和客户新闻都可能变化，应在发布当天刷新。
2. **法律与声誉风险**：标题“谁还穿着底裤”有传播力但较尖锐；正文必须继续保留“证据不足 ≠ 骗子”的护栏，不要把 C 级公司改写成欺诈事实。
3. **融资口径**：材科源图、开物纪、深度原理、深势等私营公司金额和轮次依赖公司/媒体稿，不能写成审计事实；投后估值未披露时保持“未披露”。
4. **研究机构口径**：苏州国家实验室与材料科学姑苏实验室必须分开；公共科研平台的预算、规划投资、合作资金不能写成营收或估值。
5. **公众号排版**：Markdown 不是微信最终排版文件，仍需人工粘贴、上传图片、设置摘要和检查手机端换行。当前 bundle 不直接连接微信公众号，也没有自动发布。
6. **影像图可复现性**：cinematic-v2 图片是单独生成的 raster 资产，不能由 `render-visuals.js` 自动重建；如果替换图片，必须同步修改报告中的 Markdown 路径和 README 的“当前采用版本”。

## 5. 踩过的坑：绝对不要再踩

### 事实和研究口径

- 不要把“候选材料数量”写成“新材料数量”。GNoME/A-Lab 的争议正好说明：候选、合成、性能、量产是不同阶段。
- 不要把合作协议的“最高里程碑金额”写成已到账收入；必须拆成首付款、近期里程碑、远期销售里程碑。
- 不要把注册用户、活跃科学家、合作高校、客户 Logo 写成付费客户或续费收入。
- 不要把创始人在微软/高校的旧论文和成果直接算成新公司的商业交付。
- 不要把公司官网“1200×加速”“90% 命中率”“7×24 小时闭环”等自报数字写成独立验证；一定保留“公司称/据报道”。
- 不要把融资额、投后估值、上市市值混在一张简单排名里；私营估值未披露就写“未披露”，不要自行补数。
- 不要把“融资多”当成“技术强”，也不要把“没有公开收入”当成“没有收入”。公开证据不足只能降低评级。
- 不要把研究院、实验室、开放社区按创业公司方式评价估值；先说明其法人性质和目标。
- 不要把 DeepModeling 社区等同于深势科技公司；社区影响力与公司付费客户要分开。
- 不要把“苏州实验室”作为单一机构处理，必须脚注说明苏州国家实验室与姑苏实验室的区别。

### 表达和法律风险

- 没有虚构、冒用、伪造或监管/法院认定时，不要使用“骗子”“诈骗”“庞氏骗局”作为对具体公司的事实定性。
- 可以写“资本叙事跑在证据前”“高风险”“证据不足”“宣传超出验证”，但要说明依据和缺失数据。
- 标题可以有争议，正文必须给出证据边界、来源、日期和反例。
- 不要用单一负面指标否定整个团队；例如晶泰的客户集中度是风险，不等于其收入不真实。
- 图片里的象限位置是示意，不要在正文里把示意图当作精确估值排名；图上必须保留“不可直接比较/非投资评级”说明。

### 工具和文件操作

- 不要删除或覆盖已有的 `cinematic-v2` 与 `*-3d` 图片；它们是不同视觉版本，当前主稿和 README 已有明确采用关系。
- 不要只改 README 而忘记同步主报告中的图片路径，反之亦然。
- 不要依赖相对路径给用户交付文件；对外说明使用完整绝对路径。
- 重新渲染前先确认本机 Chrome 路径和 Node/Playwright 依赖；不要直接假设 Playwright 自带浏览器已安装。
