# 批注重生成与人的声音

本参考文件只在已有草稿需要按批注重写时读取。它把“改得更像人”定义为可解释的编辑工作，不把目标写成规避检测器。

## 1. 两种模式

### `initial_generation`

输入简报、材料、来源和约束，从零构建文章。缺少事实时写成待确认项或观点，不补写亲历、客户案例、数字、引语和“行业都在用”等口碑。

### `annotation_regeneration`

输入必须同时包含：

- `brief`：主题、受众、主目标、内容形态、长度目标、禁用表达；
- `previous_generated_draft`：上一版模型生成稿，用于识别作者后续手工修改；
- `current_draft`：当前完整草稿和 `draft_version_id`；
- `active_annotations`：只包含未完成批注，每条至少有 `id`、`kind`、`note`，有选区时带 `quote`；
- `voice_profile`：作者常用词、句长和节奏、正式程度、犹豫/幽默/锋利程度，以及应保留的示例句；
- `protected_facts`：数字、日期、引语、专名、URL、来源 ID 和“可否改写”的规则。

`draft_version_id` 必须绑定当前原文指纹并在服务端复核，前后端对首尾空白使用同一规范，不能缺失时默认成 `v1`。选区批注除 `quote` 外还应带开始/结束偏移及前后文锚点；同一句重复出现且无法唯一定位时返回 `blocked`，不能默认改第一处。版本 ID 不匹配、当前稿缺失或批注无法定位时，先报告阻断，不对另一版本静默改写。

`current_draft` 是本轮权威稿。先比较 `previous_generated_draft` 与 `current_draft`，建立作者修改台账：删除的内容默认不补回；替换的术语和判断强度默认沿用；移动的段落顺序视为结构偏好；新增的限制和具体对象视为硬约束。若批注或证据要求推翻其中一项，必须在回执或未决项中点名说明，不能悄悄恢复上一生成稿。

## 2. 批注回执

每条活动批注必须有一条回执，状态只取：

- `applied`：按意见完成，指出修改后的段落或句子；
- `partially_applied`：能安全完成一部分，说明保留/未改的部分；
- `blocked`：与受保护事实、来源权限、当前稿版本或用户约束冲突，说明原因和需要用户决定的事项。

已完成批注不再消费；即使意见重复、模糊或不适合当前段落，也要回执 `blocked` 或 `partially_applied`，不能省略。回执之外提供 `remaining_risks`，让读者知道尚未解决的地方。

## 3. 事实和版权边界

- `protected_facts` 中的数字、日期、引语、专名、URL 和来源标识默认原样保留；“润色”不能把 3.2% 改成 4.1%，也不能把 URL 换成模型猜的链接。
- 服务端要从当前稿再次提取数字、DOI、型号、缩写、URL 和直接引语，不能只信任前端清单；生成后逐项做不变量校验，任何未获授权的缺失都使整次重生成回退。
- 事实核对批注没有新来源时，只能标记“待核对”、保留原句或请求材料；不得写出新的事实、客户、测试结果、引语或第一人称经历。
- “来源：待补”“依据：未知”等占位词不算证据。普通表达/结构批注若新增数字、型号、定性或定量客户口碑、稳定性/满意度、市场覆盖、行业地位或权威结论，必须阻断并改走事实核对，不能靠批注类型绕过。
- 直接引语不论长短都不改字；保护不能设置一个短到会使长引语失效的截断上限。需要压缩时只能另写转述并明确是转述，不能把转述冒充原话。
- 保护来源中的专有名词、产品型号、论文 DOI、法规/标准名称和单位格式；发现冲突时回执 `blocked`。
- 工业稿尤其要区分公开事实、厂商主张、用户材料、推断和观点；厂商或用户材料不能自动升级为独立证据。

## 4. 最小有效改写与人的声音

先通读全文，记录 3–5 个声音信号：句长变化、常用词、口语程度、保留的犹豫、幽默或锋利句。只改影响批注、事实清晰度、重复和可读性的部分；强的人类句子不因“整齐”而被抹平。

做可解释的模式扫描：

- 空泛开场： “在这个快速变化的时代”“随着……不断发展”；
- 总分总套壳：开头承诺、三段同构、结尾再次复述；
- 连续排比和机械的“一是/二是/三是”；
- 意义拔高：把一个项目写成“改变行业”“开启新纪元”；
- 二元对立模板：`不是 X，而是 Y`、`不只是 X，更是 Y`；
- 模糊权威：`专家认为`、`业内普遍认为`、`研究表明`但没有来源；
- 夸张或保证：`颠覆`、`必然`、`最强`、`零风险`、`保证提升`；
- 无对象的“赋能、闭环、抓手、生态、提效”；
- 连续同句式、同段落骨架或总结性尾句。

这些是编辑信号，不是“AI 证明”。若某模式是作者有意的语气或必要的技术表达，保留并在回执中说明，不为降低某个检测器分数牺牲准确性。

把“作者声音已经内化”做成可观察断言，而不是主观宣称：除保留作者原句外，正文后半段至少有 3 处延续作者的句长、判断顺序、常用词或克制程度。只把手改句粘在开头，随后全部改回“建议/需要/应/必须”的规程体，视为失败。

短中篇公众号稿还要做结构密度检查：一级或等效小标题通常不超过 4 个，纯文本短句标题也计数；不要连续 3 段机械复用“支持证据—反证—缺失字段—验证动作—责任人”，可压成“看什么、什么能推翻它、谁来验证”。目标字数不是固定 500 字，但工作台应把明显超长当成重复风险，通常把可见字符控制在 `min(5000, max(目标字数+300, 目标字数×1.5))` 以内。技术缩写首次出现时写中文含义；如果白话足够准确，就不用术语制造专业感。

## 5. 生成后自检顺序

1. **准确性**：受保护事实、引语、专名、URL、数字、单位和来源是否未被改动；是否新增无证据事实。
2. **批注覆盖**：每条活动批注是否有回执，回执状态与实际文本是否一致。
3. **作者修改保护**：用户相对上一生成稿的删除、改词、换序和判断强度是否保留；任何推翻是否有明确依据和回执。
4. **工业专业性**：是否把名词落到数据对象、分析方法、动作权限、流程责任和验收口径，而非能力口号。
5. **人的声音**：除保留作者原句外，后半段是否至少 3 处延续其句长、判断方式、用词和克制程度；是否删掉空泛开场、模糊权威和意义拔高。
6. **结构与长度**：短中篇是否控制在 4 个以内的一级/等效小标题；是否避免同一证据模板连续复用；是否在尊重内容目标的前提下删掉明显超长和重复。
7. **手机可读性**：段落不过长，标题兑现内容，列表只用于真正并列项，数字和链接不被断裂误读。

二次审阅不能只返回问题清单。审阅者必须先把可修问题落实到完整稿，再返回审计结果；仍有事实冲突、批注遗漏、作者修改丢失、明显模板化或审计与正文矛盾时，`passed` 必须为 `false`，前端保留原稿。

## 6.1 可解释编辑评分（提交门禁）

工作台使用 0–100 的编辑 rubric 来决定是否可以提交，不输出“AI 检测概率”，也不承诺规避任何外部检测器。第二阶段必须返回 `qualityReview.editorialScore`：

```json
{
  "total": 95,
  "threshold": 95,
  "dimensions": {
    "factualBoundaries": { "score": 25, "max": 25, "reasons": [] },
    "specificActionability": { "score": 25, "max": 25, "reasons": [] },
    "authorVoiceContinuation": { "score": 19, "max": 20, "reasons": ["后半段有一处判断顺序被改平"] },
    "antiTemplateVariation": { "score": 20, "max": 20, "reasons": [] },
    "mobileClarity": { "score": 10, "max": 10, "reasons": [] }
  },
  "deductions": [
    { "dimension": "authorVoiceContinuation", "points": 1, "reason": "后半段有一处判断顺序被改平" }
  ]
}
```

五项满分固定为：事实与边界 25、具体与可执行 25、作者声音延续 20、反模板与句式变化 20、移动端清晰度 10。桥接服务会校验分项范围、`total` 与分项之和、`deductions` 与扣分之和及每一项扣分理由；总分低于 95 直接 `review_failed`，不覆盖 `current_draft`。即使模型自报 100，确定性反 AI/事实/作者修改保护门禁仍会否决。评分是编辑质量说明，不能为了抬分牺牲准确性、证据边界或作者真实语气。

## 7. 三个现实评测场景

### 有选区批注

批注选中“系统能显著提升效率”，要求改为有对象的表述。若没有效率数据，改成“先说明它减少了哪一步人工核对”，并回执 `partially_applied`，不能凭空写百分比。

### 全局批注

批注要求“删掉套话、把结论提前”。可调整导语和段落顺序，但保留作者的技术判断、数字和不确定性；回执应指出删掉了哪些空泛句。

### 事实冲突/受保护数字

受保护事实为“2025 年内部测试，返工率 3.2%”，批注要求改成“返工率 1.8%”。没有新来源时必须 `blocked`，原数字保留或标为待核对；不得把冲突数字写入新稿。

## 8. 建议输出形状

先给改写后的完整稿，再给：

1. `draft_version_id` 和新版本 ID；
2. 批注回执表（ID、状态、改动/阻断原因）；
3. 受保护事实变更报告（默认“未变更”）；
4. 四项自检结果；
5. 仍需用户确认的问题。

若是较长文档或重要方案，增加一次“新鲜读者”检查：只把最终稿和目标读者问题交给没有上下文的审阅者，确认术语、结论和行动要求不会被误读，再回到作者做最后决定。

- [Ryan Maule humanize](https://github.com/ryanmaule/humanize/blob/main/SKILL.md)、[Shir Danishyar humanize](https://github.com/shir-danishyar/humanize/blob/main/SKILL.md)：保留作者声音、最小有效编辑、保护引语/数字/链接，并把“检测”与“改写”分开。
