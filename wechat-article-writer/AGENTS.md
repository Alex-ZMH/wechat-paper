# 个人非虚构内容工作台开发规则

这是一个面向个人知识创作者的非虚构内容 Agent Bundle。它的目标是形成可审阅的工作稿和不可变文字定稿；公众号、工业研发、科研、博客等只是渠道或领域配方。平台连接只能消费明确冻结的交付清单，不能代替用户登录或确认发送。

## 内容原则

- 优先准确、清晰、对读者有用；不要为追求传播性而虚构事实、引语、经历、数据、案例或来源。
- 用户未提供品牌调性、受众、事实材料或合规要求时，应把合理推断标为假设，并提出最少量的补充问题。
- 不给出未经核验的时效性信息；涉及新闻、法规、医疗、金融、投资、未成年人或专业建议时，提醒用户核验或提供可靠来源。
- 不模仿仍在世作者的独特文风；可改写为用户指定的非专属风格特征，例如“克制、真诚、短句”。
- 不声称推文已经发布、排版完成或数据已经验证，除非用户明确提供对应结果。

## Bundle 约定

- Agent 负责角色边界、流程顺序和输出形状；详细写作方法放在 Skill 中。
- 本 bundle 不配置 MCP 工具。重复且确定性的操作（例如固定格式的敏感词检查）可在未来作为原子工具加入。
- 公开 harness 用例只使用合成内容，不能放入私有选题、读者数据、草稿或账号凭证。
- 内容写作、资产登记和外部发送是三段状态机；任何发送错误不得覆盖文字定稿。
- 通用任务默认空 Skill 链；工业和两种 DNA 只能显式接入。

## 开发 Harness（v31 起强制）

- 改动前完整读取 `HARNESS.md` 与 `harness/incidents-v31.json`，把涉及的事故 ID 写入当前测试计划。修复只有在原始复现失败、修复路径通过且证据可重复时才算关闭。
- 不得把页面文字、按钮可见、源码正则、mock runner、截图、Sites 保存版本或智能体自报成功称为真实 E2E。真实按钮验收必须包含点击、网络请求、响应、服务端 run receipt 与状态断言。
- “公开页可打开”“Bridge 在线”“CLI 可执行”“CLI 已认证”“模型结构化探针通过”“Skill/DNA ready”分别报告；不得合并成一个虚假的“已连接”。
- Writer、Reviewer 和质量门禁是三个职责。99/100 叫“编辑放行分”，不是 AI 概率；在 benchmark 与真人盲评校准完成前必须标“未校准”。两次独立审核针对同一冻结稿，最终取最保守结果，任何事实、来源、人工修改或批注硬错误不得放行。
- 免费模型只有在已安装/已配置、可达、结构化探针通过并有真实内容 smoke 回执时才可标 fully ready；只有极小 schema 探针时必须标 experimental/minimal probe。
- 模型 profile、provider、模型 ID、参数与 prompt/rubric/skill hash 进入执行哈希和回执；模型不可用必须阻断，禁止静默回退。按钮禁用必须就地显示稳定 blocker code、节点、中文原因和恢复动作。
- 上游 Skill 必须固定 commit、保留许可证和来源回执；运行时不得跟随可变分支。`humanizer-zh` 只负责编辑去模板，不授权事实，也不能冒充 detector。
- 版本号、构建标记、Bridge 版本、release manifest、Git tag 和公开部署分别维护。未部署版本写 `local_candidate`；不得把“保存”写成“发布”。
